* Purpose

This file is the literate source of the chemoinformatics worked
example. It ships:

- A *small synthetic SMILES dataset* — eight Lipinski-friendly drug-like
  scaffolds drawn from public textbook chemistry (aspirin, ibuprofen,
  caffeine, paracetamol, and four small Bemis–Murcko cores). The
  dataset is hand-curated and bundled into the repository so the
  example runs anywhere without external data fetches.
- A *deterministic descriptor pipeline*: SMILES → RDKit descriptors
  (molecular weight, LogP, TPSA, hydrogen-bond donors/acceptors) →
  Lipinski Rule-of-Five violation count.
- A *templated synthetic-prediction layer* — a deterministic-but-
  string-templated function that takes the descriptors and emits a
  "SAR-style insight" string. This is the layer that *would be* an
  LLM call in a real drug-discovery workflow; we substitute a
  templated string so the example is reproducible and license-clean,
  while keeping the register honest (~synthetic-acknowledged~).
- Three manifests demonstrating a typical chemoinformatics workflow.
  One is doctrinally correct; two are deliberately broken in ways
  that catch the LLM-induced sins the firewall is designed to
  prevent.
- A pytest test file that exercises the workflow end-to-end and
  asserts that the broken manifests fail with the expected B-class
  messages.

** Why a chemoinformatics example, when sakshi was built for environmental data?

sakshi's doctrine is a property of /scientific data pipelines under
LLM pressure/, not of any single domain. The four-register firewall
and the two-mode polymorphism apply identically whenever:

1. There is a measurement substrate (here: a SMILES string is a
   measurement of an actual chemical compound).
2. There are derived quantities (here: descriptors like LogP, TPSA,
   computed deterministically from the measurement).
3. There is an LLM-or-synthetic layer that produces plausible-looking
   outputs not anchored to the measurement (here: the
   "SAR-style insight" string).

The chemoinformatics worked example exists to show this portability
explicitly. If sakshi only ever demonstrates itself on its native
substrate (environmental-sensor time series), a reader might fairly
ask whether the discipline is a property of the doctrine or a
property of the substrate. This example settles the question:
*nothing in sakshi's schema or firewall mentions chemistry*. The
manifests work because the doctrine is substrate-agnostic.

** What this example does NOT do

- It does not call RDKit's full machine-learning stack. The
  descriptors are deterministic, license-clean, and identical across
  RDKit versions for the small bundled scaffolds.
- It does not call an LLM. The "SAR-style insight" layer is a
  templated string built from the descriptors. The discipline being
  demonstrated is independent of whether an LLM is actually invoked
  — the register is what matters.
- It does not claim domain expertise. The descriptor choices and the
  Lipinski Ro5 framing are textbook chemoinformatics; the worked
  example demonstrates sakshi's discipline applied to a faithfully-
  shaped chemistry pipeline, not novel medicinal-chemistry insight.

"""Hand-curated small SMILES dataset for sakshi's chemoinformatics example.

This file is tangled from codev/examples/chem.org.

Each entry is a public, textbook drug-like compound or a small
Bemis–Murcko core. SMILES strings are copied from PubChem entries
(public-domain compound identifiers; no proprietary structures).

Columns when written to CSV:
    compound_id  -- short identifier
    name         -- common name
    smiles       -- canonical SMILES
"""

from __future__ import annotations

from pathlib import Path

SMILES_SEED = [
    # Drug-like reference compounds (public textbook chemistry).
    ("ASP", "aspirin",     "CC(=O)Oc1ccccc1C(=O)O"),
    ("IBU", "ibuprofen",   "CC(C)Cc1ccc(C(C)C(=O)O)cc1"),
    ("CAF", "caffeine",    "Cn1cnc2c1c(=O)n(C)c(=O)n2C"),
    ("PCM", "paracetamol", "CC(=O)Nc1ccc(O)cc1"),
    # Small Bemis–Murcko-style scaffolds for descriptor variety.
    ("PYR", "pyridine",    "c1ccncc1"),
    ("IND", "indole",      "c1ccc2[nH]ccc2c1"),
    ("QIN", "quinoline",   "c1ccc2ncccc2c1"),
    ("THI", "thiazole",    "c1cscn1"),
]


def write_csv(out_path: Path) -> None:
    """Write the seed dataset to a CSV at out_path."""
    out_path.parent.mkdir(parents=True, exist_ok=True)
    lines = ["compound_id,name,smiles"]
    for cid, name, smi in SMILES_SEED:
        lines.append(f"{cid},{name},{smi}")
    out_path.write_text("\n".join(lines) + "\n")


if __name__ == "__main__":
    write_csv(Path(__file__).parent / "smiles_seed.csv")

* The descriptor and Lipinski layers

This is the deterministic, RDKit-backed derivation layer. Given a
SMILES string, RDKit emits a fixed set of physico-chemical descriptors
(molecular weight, LogP, TPSA, HBD count, HBA count). Lipinski Rule-of-
Five violation count is then computed from those descriptors by a
textbook formula.

The register of these outputs is ~derived-from-measurement~. The
~derivation~ field names the procedure ("rdkit-descriptor-suite-v2024"
and "lipinski-ro5-violation-count").

If RDKit is not installed, the test file skips the workflow tests; the
manifest-level tests run regardless.

#+begin_src python :tangle ../../test/chem/descriptors.py
"""Deterministic descriptor and Lipinski-Ro5 layer for the chem example.

This file is tangled from codev/examples/chem.org.

Optional dependency: RDKit (install with `pip install sakshi[chem]`).
If RDKit is not available, descriptor functions raise ImportError and
the test runner skips the workflow tests.
"""

from __future__ import annotations

from dataclasses import dataclass

try:
    from rdkit import Chem
    from rdkit.Chem import Crippen, Descriptors, Lipinski

    RDKIT_AVAILABLE = True
except ImportError:  # pragma: no cover
    RDKIT_AVAILABLE = False


@dataclass(frozen=True)
class MolDescriptors:
    """The fixed descriptor suite produced by rdkit-descriptor-suite-v2024."""

    compound_id: str
    molecular_weight: float
    logp: float
    tpsa: float
    hbd_count: int
    hba_count: int


def compute_descriptors(compound_id: str, smiles: str) -> MolDescriptors:
    """Compute the descriptor suite for a single SMILES.

    Procedure name: rdkit-descriptor-suite-v2024
    """
    if not RDKIT_AVAILABLE:
        raise ImportError(
            "RDKit not installed. Install with `pip install sakshi[chem]`."
        )
    mol = Chem.MolFromSmiles(smiles)
    if mol is None:
        raise ValueError(f"RDKit could not parse SMILES for {compound_id!r}: {smiles!r}")
    return MolDescriptors(
        compound_id=compound_id,
        molecular_weight=round(Descriptors.MolWt(mol), 2),
        logp=round(Crippen.MolLogP(mol), 2),
        tpsa=round(Descriptors.TPSA(mol), 2),
        hbd_count=Lipinski.NumHDonors(mol),
        hba_count=Lipinski.NumHAcceptors(mol),
    )


def lipinski_violations(d: MolDescriptors) -> int:
    """Count the number of Lipinski Rule-of-Five violations.

    Procedure name: lipinski-ro5-violation-count

    Ro5 (Lipinski 1997): a drug-like molecule typically has
        MW <= 500, LogP <= 5, HBD <= 5, HBA <= 10.
    """
    violations = 0
    if d.molecular_weight > 500:
        violations += 1
    if d.logp > 5:
        violations += 1
    if d.hbd_count > 5:
        violations += 1
    if d.hba_count > 10:
        violations += 1
    return violations
#+end_src

* The templated synthetic-prediction layer

This is the layer that would be an LLM call in a real workflow. We
substitute a deterministic templated string so the example is
reproducible and license-clean.

Crucially, the register stays honest: the output is
~synthetic-acknowledged~, with a ~synthesis~ field naming the procedure
("templated-sar-insight-stub" — replaced in production by an actual
LLM-call procedure name like "claude-opus-4-6-medchem-prompt-v3").

The point of this layer is *not* that the templated string is useful
chemistry — it isn't. The point is that the discipline treats this
class of output identically whether the generator is a templated
string or a state-of-the-art chemistry LLM. The register is the
honest answer to "where did this come from?"

#+begin_src python :tangle ../../test/chem/insight.py
"""Templated synthetic-prediction layer for the chem example.

This file is tangled from codev/examples/chem.org.

The function in this file would, in a production drug-discovery
workflow, be a call to an LLM (Claude, GPT-4, a medchem-fine-tuned
model). We substitute a deterministic templated string so:

1. The example runs anywhere without API keys.
2. The output is bit-identical across runs.
3. The discipline being demonstrated does not depend on the actual
   text content — it depends on the *register*.

The register is ~synthetic-acknowledged~, and the manifest's
~synthesis~ field names the procedure honestly.
"""

from __future__ import annotations

from .descriptors import MolDescriptors


def sar_insight_stub(d: MolDescriptors) -> str:
    """Emit a templated SAR-style insight string from descriptors.

    Procedure name: templated-sar-insight-stub

    In production, replace with an LLM call:
        sar_insight_llm(d) -> calls claude-opus-4-6 with a medchem prompt
    The register remains 'synthetic-acknowledged' in both cases.
    """
    permeation = "likely cell-permeable" if d.logp < 5 and d.tpsa < 90 else "permeation uncertain"
    drug_like = "within Lipinski-friendly range" if d.molecular_weight <= 500 else "above typical drug-like MW"
    return (
        f"Compound {d.compound_id}: LogP={d.logp} and TPSA={d.tpsa} — "
        f"{permeation}; molecular weight {d.molecular_weight} places it "
        f"{drug_like}; donor/acceptor profile ({d.hbd_count}/{d.hba_count}) "
        f"is balanced for oral bioavailability."
    )

def test_chem_manifest_uses_no_chemistry_specific_schema_fields():
    """The chem manifest uses only generic sakshi schema fields.

    This test makes the substrate-portability claim concrete:
    everything in the chem manifest is built from sakshi's generic
    vocabulary (register, derivation, synthesis, mode). Nothing in
    sakshi's schema mentions chemistry. If the doctrine were
    domain-specific, this test would be impossible to write.
    """
    import yaml

    raw = yaml.safe_load(
        (MANIFESTS_DIR / "01_chem_correct.manifest.yaml").read_text()
    )
    # The only domain-specific strings are in `description` and
    # `derivation`/`synthesis` *values* — i.e., free-form text the
    # schema does not constrain. The *keys* are all generic.
    chem_specific_keys = {"smiles", "molecule", "compound", "rdkit", "lipinski"}

    def walk_keys(obj):
        if isinstance(obj, dict):
            for k, v in obj.items():
                yield k
                yield from walk_keys(v)
        elif isinstance(obj, list):
            for item in obj:
                yield from walk_keys(item)

    keys = set(walk_keys(raw))
    leaked = keys & chem_specific_keys
    assert not leaked, (
        f"Chemistry-specific keys leaked into the manifest structure: {leaked}. "
        f"sakshi's schema should not need chemistry-specific extensions."
    )

* What this example demonstrates

Concretely, the chemoinformatics worked example demonstrates:

1. *Substrate portability*. sakshi's doctrine is a property of the
   /shape/ of scientific data pipelines, not of any specific domain.
   The chem manifests work because they use only generic vocabulary
   (register, derivation, synthesis, mode). The test
   ~test_chem_manifest_uses_no_chemistry_specific_schema_fields~
   makes this claim falsifiable.

2. *The synthetic-acknowledged register is the honest answer*. The
   "SAR insight" layer is a templated string in this example and
   would be an LLM call in production. The register is identical
   either way. The discipline does not depend on whether the
   generator is statistical, deterministic, or neural — it depends
   on whether the manifest names the synthesis procedure honestly.

3. *Two real LLM-induced sins, caught at parse-time*. The two broken
   manifests catch the two most common errors when an LLM helps an
   engineer write a manifest:
   - Labelling the register correctly but forgetting the
     ~derivation~ field (the engineer or model knows the output is
     derived but doesn't name how).
   - Labelling the register correctly but forgetting the
     ~synthesis~ field (the engineer or model knows the output is
     generative but doesn't name how).
   Both are B-class — they fail at parse, before any pipeline runs.

4. *Optional dependency discipline*. RDKit is an optional dependency
   (install via ~pip install sakshi[chem]~). The manifest-level
   tests run without it; the pipeline-execution tests skip cleanly.
   This is the pattern for domain-specific worked examples that
   shouldn't bloat the core install.
